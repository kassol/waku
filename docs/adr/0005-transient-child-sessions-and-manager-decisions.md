# 子会话临时执行与管家统一交互

2026-09-07，用户确认主会话承担日常交互和最终交付；子会话用于分担上下文和并行执行。子会话完成生命周期后归档并从日常会话列表隐藏，完整记录保留，主会话留下执行摘要与可追溯入口。此决策延续 ADR 0001 的历史保留要求。

子会话的问题统一交给管家。管家根据用户目标及已有授权处理技术选择和已授权操作；新增范围、费用或权限需求由管家在主会话集中询问用户。派发前明确可预见的约束，执行中出现的问题按同一授权边界处理。此决策替代 ADR 0002 中“由用户在子会话中处理、管家不代答”的交互约定；直属管理范围和权限上限继续有效，管家代决不产生新的权限授权。

管家与直属子会话采用双向沟通。管家下达任务、补充约束、反馈与决定；子会话回报成果，也可主动请求澄清、报告阻塞或提出需要决定的方案。普通进度不触发管家重复协调，需要决定的问题与完成结果通过事件通知管家。

子会话提出决策请求时，保存问题、必要背景、可选方案及受阻工作，进入明确的等待决策状态。管家处理授权内事项；需要用户决定时转到主会话，相关子会话继续等待，其他独立任务继续执行。管家等待结果期间收到决策请求，应先处理该请求，避免父子双方互相等待。管家忙碌时请求可靠保留，待其可处理时送达。

等待由持久记录和事件恢复驱动，双方没有可独立推进的工作时释放当前执行轮；原生审批或提问需要保留挂起请求时，沿用 harness 的等待能力，不通过模型轮询维持运行。决定关联原请求，经确认接收后恢复受阻工作；送达不确定、重复通知、取消及重启不能导致重复执行或将过期决定应用于新问题。需要审批的操作始终保留原生权限核验。主会话保留问题、决定及结果摘要，存在未处理决策的子会话尚未完成生命周期。

归档发生在结果已由管家接管、摘要与成果证据可靠保存且无需该子会话继续处理之后。一次轮次结束不能单独作为生命周期完成依据。失败任务由管家决定重试、替代或终止，并保留失败原因。会话归档与 Git 资源清理分别判断，无法安全清理的资源继续保留并在主会话说明原因。

这是已确认的产品方向，尚未实现。相关行为已整理为 [Issue #23](https://github.com/kassol/waku/issues/23) 的生命周期规格，已拆为 #24–#30，待实现；该规格不包含升级自动归档或批量整理历史子会话，本轮不迁移或删除既有会话。
