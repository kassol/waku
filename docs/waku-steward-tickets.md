# 管家一期任务拆分草案

父规格：[kassol/waku#1](https://github.com/kassol/waku/issues/1)。状态：待用户确认粒度及阻塞关系，尚未发布子任务。

T 编号仅用于本轮审阅。确认后按依赖顺序创建 GitHub Issues，用实际 Issue 编号替换阻塞项并建立原生依赖。保留父规格原文和状态，不关闭或编辑父规格。

每票在自己的行为范围完成接口、持久化、必要的界面及回归验证；前置票可从现有 daemon 协议验收，MCP 可用后优先从工具入口验收。协议变化同步检查 Rust 和共享 TypeScript 客户端。使用隔离测试资源，每票完成 Standards / Spec 两轴评审；测试通过后再提交。所有新增控件在所属票内具备键盘路径，性能与可访问性不留到末票补做。

票的创建不代表立即开工或解除暂缓安装工具链的约束。首次实现和工具链安装继续遵循当前授权；测试启动必须先通过隔离检查。没有独立预重构票：必要的历史逻辑提取在 T02 内先保持原有行为，再实现 daemon 保存。

## T01：测试 App 独立启动与资源隔离

### Parent

https://github.com/kassol/waku/issues/1

### What to build

测试 App 能使用自己的 Waku 资源完成启动、保存和停止，原版 App 的安装、进程和自有数据保持不动，并具备后续功能验证的构建基线。

### Acceptance criteria

- [ ] 测试身份与原版区别明确；Waku 配置、数据库、daemon、工作目录、辅助程序、缓存及进程控制均处于测试范围。
- [ ] 启动不会因继承外部 daemon 环境变量连接原版；停止、清理和更新仅作用于测试实例；普通原版身份 Release 包不能误作测试包。
- [ ] 临时“原版”文件与进程哨兵在启动、保存、辅助程序安装和停止检查后保持不变，避免用真实数据做破坏性测试。
- [ ] 允许共用原生 Claude/Codex 配置和会话目录；验证使用新会话与专用工作区，不改写共用服务配置或清理原有原生会话。
- [ ] 在具备已获授权的工具链后完成项目构建检查，通过现有唯一 watcher 启动签名测试 App；未具备工具链或隔离未通过时明确记录阻塞，不能声称本票验收通过。

### Blocked by

None（可在获得实现授权后开始；工具链安装仍遵循既有约束）。

## T02：无人查看时仍保存并恢复会话历史

### Parent

https://github.com/kassol/waku/issues/1

### What to build

现有 Claude/Codex 会话的事件由 daemon 自主保存，用户稍后打开或重连后读到同一段历史，并能看见内容是待保存还是已保存。

### Acceptance criteria

- [ ] 没有客户端查看会话或参与历史归并时，daemon 仍能持久保存原生顺序的内容；复用已有历史表示及解释语义。
- [ ] 仅可靠持久化完成后确认已保存，界面显示待保存/已保存/失败；发出 notify 或进入内存队列不等于保存。
- [ ] 从现有 daemon 接口运行可控事件后重新打开数据库或连接客户端，读回正确历史，无重复或静默缺失；重放与在线流有明确衔接边界。
- [ ] 同版本多个客户端、重复事件和旧视图保存不覆盖较完整历史；不兼容协议版本在操作前拒绝，相关协议类型同步。
- [ ] 保存与重放不阻塞 UI，长历史继续按需加载。队列压力不能丢弃转录；本票不启用尚无安全条件的事件清理。

### Blocked by

- T01：测试 App 独立启动与资源隔离。

## T03：创建可打开的 Codex 子会话及父子关系

### Parent

https://github.com/kassol/waku/issues/1

### What to build

通过统一 daemon 创建入口，从一个已有管家会话创建默认使用 worktree 的 Codex 子会话，执行首轮输入，并在 App 中发现和打开该子会话。

### Acceptance criteria

- [ ] 创建入口处理项目验证、Codex 启动、默认 worktree、首轮输入和持久化；返回真实会话标识、目录及分支。worktree 不可创建时明确失败，不降级为共享目录。
- [ ] 子会话权限不高于父会话；父子关系由 daemon 管理，完整快照、落后快照及列表/详情加载均保留该关系。
- [ ] App 收到目录变化后在现有会话列表中显示子会话，可用键盘打开并阅读首轮结果；树形导航由 T09 交付，此票不新增手工创建子会话的额外产品入口。
- [ ] 从现有 daemon 协议到真实临时数据库和 Git 工作区验证完整链路，重连后父子关系与历史仍在。
- [ ] 创建失败不伪报成功；已使用或已修改工作区不会被自动清理。该票仅承诺单次创建，幂等重试与可选工作区由 T07 交付。

### Blocked by

- T02：无人查看时仍保存并恢复会话历史。

## T04：Claude 管家通过 MCP 创建 Codex 子会话

### Parent

https://github.com/kassol/waku/issues/1

### What to build

用户创建 Claude 管家会话后，管家通过 MCP 创建 Codex 子会话，用户在现有会话列表中打开它并看到实际执行结果。

### Acceptance criteria

- [ ] 复用 daemon 二进制提供 stdio MCP 子命令，经现有 WebSocket 鉴权连接所属 daemon；协议标准输出不混入日志。
- [ ] Claude 管家入口使用按会话 MCP 配置；不改写共用 CLI 配置。MCP 上下文绑定管家和项目，不能通过工具参数伪造父会话。
- [ ] `waku_spawn_session` 贯通统一创建与持久化，返回真实标识、目录和分支；子会话出现在现有列表，用户可打开查看执行结果。
- [ ] 创建上下文固定为所属管家和项目，不能伪造父会话、跨项目创建或提升子会话权限；不把通用桌面管理接口暴露给模型。
- [ ] 自动回归从 MCP 入口贯穿真实 daemon、临时数据库和 Git 工作区；在隔离测试 App 中走通 Claude 管家创建 Codex 子会话并由用户打开查看结果。
- [ ] 本票不宣称后续工具和选项已实现；列表、状态、结果、后续输入、取消、创建幂等由对应票交付，不能用返回假成功的占位实现代替。

### Blocked by

- T03：创建可打开的 Codex 子会话及父子关系。

## T05：查询直属子会话状态与结果

### Parent

https://github.com/kassol/waku/issues/1

### What to build

管家通过列表、状态和结果工具完成查询闭环，能批量等待直属子会话的变化，并读取带轮次、结束状态和截断说明的回复及可选历史。

### Acceptance criteria

- [ ] `waku_list_sessions` 仅返回直属子会话摘要；列表、状态和结果均校验直属范围，不支持扩大范围的 parent_only=false。
- [ ] `waku_status` 支持多个直属会话，wait_ms 默认 0，范围 0 至 60000；非法值明确失败，变化或超时后返回当前状态，超时不算任务失败。
- [ ] 会话状态与当前/最近轮次状态分别返回；无轮次明确为空，Idle、Background、Waiting 不能误报该轮成功。
- [ ] `waku_result` 覆盖工具事件穿插文本、未结束轮次、没有轮次和失败/中断；回复保持原生顺序，不能只取最后几个文本增量或上一轮结果。
- [ ] include_transcript 默认关闭，max_chars 截断保持字符边界并给出标识；读取不改写历史，provider 正常结束不声称代码已经验收正确。
- [ ] 同时运行、晚订阅和读取结果的回归不重复或漏掉状态，等待与提取工作不阻塞 UI；越权目标不返回其他会话内容。

### Blocked by

- T04：Claude 管家通过 MCP 创建 Codex 子会话。

## T06：Claude 子会话、递归委派与用户审批

### Parent

https://github.com/kassol/waku/issues/1

### What to build

管家也能派生 Claude 子会话；Claude/Codex 子会话可作为下一层管家管理自己的直属子会话。需要权限审批或用户回答时，用户进入对应子会话处理。

### Acceptance criteria

- [ ] `waku_spawn_session` 支持 Claude 子会话，创建、历史、状态、结果、父子关系及现有列表打开与 Codex 遵循相同契约。
- [ ] 两种 provider 均通过按会话配置获得 MCP，递归委派仍使用同一 daemon 和统一创建能力，不改写原生全局配置。
- [ ] 上层管家不能通过 MCP 直接操作孙级会话，下一层只能操作自己的直属子会话；每层父子关系重连后仍可观察。
- [ ] 跨 provider 继承不高于父会话的权限；无法安全映射时明确拒绝，不回退到更高权限。
- [ ] 状态明确区分等待审批与等待回答，用户可通过键盘进入子会话处理；管家只获知等待，不代答，不将等待或 Background 状态当作完成。
- [ ] 可控 provider 回归覆盖递归范围和审批；隔离测试 App 验收真实 Claude 子会话流程。

### Blocked by

- T05：查询直属子会话状态与结果。

## T07：可恢复的创建重试与工作目录选择

### Parent

https://github.com/kassol/waku/issues/1

### What to build

管家在断连或创建失败后能识别已发生的工作，使用幂等键重试不会重复创建或重复提交首轮，并可明确选择工作目录。

### Acceptance criteria

- [ ] 幂等键按管家隔离；相同键与相同请求返回同一结果，不重复建会话、worktree 或提交首轮；不同请求使用相同键明确冲突。
- [ ] 幂等记录在 daemon 重启后仍有效；没有键时明确不承诺重试去重，接收状态不明不自动重复执行。
- [ ] 默认 worktree；inherit 使用父会话实际目录，local 使用项目普通检出目录；返回实际目录，不静默改变用户选择。
- [ ] 在目录创建、持久化、provider 启动和首轮提交各阶段失败时，返回明确结果及已产生的会话信息；只有本次新建且可证明未使用的资源才可自动清理。
- [ ] 以已有 Codex 创建流程完成故障及重启回归，保持 provider 通用契约。错误或部分结果在 App 可见，已修改工作区和原有数据保持不动。

### Blocked by

- T04：Claude 管家通过 MCP 创建 Codex 子会话。

## T08：后续输入与取消当前执行

### Parent

https://github.com/kassol/waku/issues/1

### What to build

管家能向直属子会话发送新轮次输入或取消当前执行，用户可在子会话中看到对应轮次、停止状态及保留的历史。

### Acceptance criteria

- [ ] `waku_prompt` 在 daemon 可靠保存输入和轮次标识后返回 turn_id；已有开放轮次或等待用户时明确拒绝，不自动排队或转换为 steer。
- [ ] 输入接收状态因断连变得不确定时不自动重发，调用方可查询当前或最近轮次标识与状态；provider 后续失败有明确状态。
- [ ] `waku_cancel` 可重复调用，区分取消受理与实际停止；仅在停止确认后收敛为 Interrupted，不报告为正常完成。
- [ ] 取消不删除历史、不回滚修改、不隐式取消其他会话；新一轮结果不会退回上轮成功回复。
- [ ] 两个工具都强制直属范围；MCP 回归覆盖忙碌、断连、重复取消和轮次切换，App 对应状态与原生执行一致。

### Blocked by

- T05：查询直属子会话状态与结果。

## T09：父子导航与长期历史保留

### Parent

https://github.com/kassol/waku/issues/1

### What to build

用户通过树形导航阅读父子会话，长时间未打开的历史在内部事件清理后仍完整；删除父会话后，尚未删除的后代仍可发现。

### Acceptance criteria

- [ ] 侧边栏显示父子层级，支持键盘展开、定位和打开子会话，保持原有会话可发现性与按可见范围构建。
- [ ] 可读历史保留至用户主动删除；20000 条/90 天仅作用于已保全历史且满足恢复要求的冗余事件。
- [ ] 客户端长期未打开、清理与重放并发、清理后重启均不造成历史缺失或重复；尚未安全保全的事件不被裁剪。
- [ ] 同版本旧快照写回、完整替换及详情重载不会擦掉父子关系或较完整历史。
- [ ] 删除父会话不隐式删除后代历史或已修改工作区；用户仍可找到后代及可解释的来源，不重新归属到其他管家。
- [ ] 使用临时数据库超过裁剪门槛并重开验证，侧边栏导航和长历史按可见范围工作；不增加无需求的归档系统。

### Blocked by

- T03：创建可打开的 Codex 子会话及父子关系（已包含 T02）。

## T10：保存失败停止任务与安全退出恢复

### Parent

https://github.com/kassol/waku/issues/1

### What to build

持续保存失败时用户能看见未保存边界，受影响任务停止；正式退出 App 时停止所属任务并等待保存，异常退出后恢复可靠数据。

### Acceptance criteria

- [ ] 持续写入失败时停止受影响任务并拒绝新任务，保留可恢复数据，显示错误和未确认保存的内容；队列压力不通过丢弃转录处理。
- [ ] 正常退出按停止接收新任务、停止运行并处理尾部事件、确认保存、退出所属 daemon 的顺序完成，不能以 fire-and-forget 请求或超时强杀冒充保存成功。
- [ ] 保存失败不显示安全保存成功；强制终止只承诺恢复已确认保存的数据，待保存部分有明确风险提示。
- [ ] 重启后失去运行时的未结束轮次收敛为 Interrupted，清除失效审批与提问交互，不自动重发输入或恢复旧审批请求。
- [ ] 使用现有会话和可控 provider 验证写入故障、正常退出和崩溃边界；只停止测试实例管理的进程，不干扰原版。本票使用现有 daemon 控制入口独立验收，T11 验证与 MCP 管理会话的集成。

### Blocked by

- T02：无人查看时仍保存并恢复会话历史。

## T11：长历史多会话下的原生交互验收

### Parent

https://github.com/kassol/waku/issues/1

### What to build

在完整一期功能合入后，用户可在多个运行子会话和长历史中流畅导航、处理审批、读取结果及退出恢复，完成真实 Claude/Codex 全链路验收。

### Acceptance criteria

- [ ] 在隔离且由唯一 watcher 管理的签名测试 App 中验证六工具完整流程，覆盖 Claude/Codex 子会话、层级导航、用户审批、重试、取消及退出恢复。
- [ ] 使用项目既有性能测量方法检查多个流式会话、长历史、重放与保存；逐帧路径无阻塞 I/O，工作量保持与可见范围相关。
- [ ] 所有新增可见操作有键盘路径与焦点，减少动态效果生效，状态不依赖颜色或悬停；发现集成回归在本票修复。
- [ ] 临时隔离哨兵检查继续通过，原版安装、进程与自有数据保持不动；清理测试产生的临时服务与资源，保留有用户工作成果的内容。
- [ ] 完成项目整体基线及 Standards / Spec 评审，提供可重现的行为与性能证据；测试通过前不把规格视为交付完成。
