## 公共组合流程

`crates/waku-core/src/collaboration_lifecycle_tests.rs` 在真实 daemon socket、SQLite 和调度边界中使用受控 `QueueDriver`。同一任务包含两个直属子任务和一个嵌套子任务，分别执行普通代决、原生类型化响应、嵌套转问及真实用户回答。父轮忙碌时通知保留；分别运行“独立成果先到”和“用户答复先到”两种顺序。收到一批成果后，通过公开 `waku_wait` 为剩余工作重新登记等待。

每种顺序精确核对：主会话回调 3 次、嵌套管家成果回调 1 次、普通决定投递 1 次、原生响应 1 次、嵌套用户答复投递 1 次。重复决定与回答没有新增执行，重复接管仍为主会话 2 条摘要、嵌套管家 1 条摘要。12 条普通进度事件触发 0 个额外模型轮次。测试驱动等待屏障不属于模型轮询；该序列没有模型轮询调用。没有测量费用或真实任务耗时，未据此承诺费用、时延或帧率改善。

`steward_input_tests.rs`、`task_continuation_tests.rs` 和已有工作区测试继续覆盖取消、新方向、父轮忙碌、失效原生请求、零写入或部分写入、重启不重送、保存失败回滚、活动后代、待决事项及无关工作区保护。旧会话缺少新增字段时按默认值读取，未自动归档或迁移。

## 原生与 Git 验收

#27 分别通过真实 Codex 和 Claude 的一次隔离兼容验证：原始请求 ID、实际 Transport 接收、输出文件与完成轮次一致。`27-live-codex.log`、`27-live-claude-fixed.log` 保存结果。受控 driver 的公共测试不替代这两项真实进程证据；本轮后续变更没有改写 provider 响应实现。

签名 Debug 全程通过后台 CUA 操作，不激活前台或使用系统键鼠注入。主会话回答两个原生问题（JSON、Evidence），子会话通过原数字请求 500 收到答案并继续原轮；管家保持已保存等待，子任务结束后收到一次最终回调。来源历史保留原问题、回答和过程。

归档验收直接比较消息、轮次、活动块和决定记录，首次完成与重复完成返回同一完成 ID。主会话即时出现摘要，来源链接打开只读历史，日常列表隐藏归档子任务；打开历史没有启动 runtime 或切换分支。

继续验收覆盖主摘要与归档详情入口。输入新指令、Tab 定位提交、Return 提交一次，显示 Transport Received；Escape 返回，原消息及完成记录保持。已移除工作区的公共回归确认重新委派一次，并把固定旧摘要提供给新子任务。脏目录、外来目录、权限变化、已交付父任务及嵌套模型伪造用户授权均拒绝执行。

实际后台流程两次走通：受控进程写入 `continuation-output.txt`，按固定提交集成，第二次接管保留首次完成记录，再交付临时仓库目标分支。最终两个临时仓库提交分别为 `072b22fa3668099b481c03fef5cf0e133f2fad6b` 和 `9cb7c51486b92f58c18df38768e87db6f8b27d0c`。产品清理移除子工作区后，消息、轮次、活动块、决定、完成记录和继续记录逐项相同；来源链接仍显示完整只读历史。再次继续已交付任务被拒绝，保留现有交付。

另用独立的 300 条消息验证历史末尾、较早消息导航、输入区布局与可见键盘焦点。该检查不包含帧率测量，也不声称验证搜狗输入法候选窗定位。

## 验收中修复的问题

- 首个桌面订阅者编号为 0；daemon 通知误把 0 当来源排除，导致归档或原生回执已保存但界面不更新。改用既有 daemon 广播约定，并用首个客户端及实际原生界面复验。
- 替代任务最初只收到继续指令；现提供原完成记录的固定摘要和原始用户指令，保留来源关联。晚到 Accepted 快照也不能覆盖较新的 Received。
- 第二次完成摘要曾被插入旧摘要前。共享消息合并现在选择实际前序消息与前序轮次末尾中较后的位置，保留独立生成的 assistant ID 兼容性。新增回归与第二次原生流程确认“旧摘要 → 新用户指令 → 新摘要”。
- 归档保护曾全程占用父任务，阻止并行创建。普通创建现在只在工作区锁内校验并持久登记；归档在同一锁内检查未完成创建记录。既有同键幂等、不同键并行和关机测试通过；新增公共回归确认在建任务拒绝归档，独立创建继续，后代接管后才允许归档。
- 更新旧测试以核对完整 14 个工具及新的原生转问流程；保留越权拒绝。补齐中文与日文目录缺失键，现有翻译保持不变，占位符一致。
- 成果回调文字沿用当前授权规则：授权内由管家处理，新增范围、费用或权限回主会话；保留结束当前轮与事件恢复要求。
