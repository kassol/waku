# 动态分工与集中反馈

管家指导随 MCP `initialize` 返回，源码为 `crates/waku-core/src/steward_guidance.txt`。短任务可直接完成；长时间实现和验证按实际依赖委派。每次委派的首轮输入记录负责人角色、范围、基线、依赖和验收目标；返回的子会话 ID 确定负责人。已有会话历史保留分工和调整，`ManagedWorkspace` 保留基线、依赖和固定成果证据。

`waku_results` 接收 1–128 个直属子会话 ID，按输入顺序去重。运行中的子会话返回状态；终态、失败原因、审批或用户问题使结果可处理。一次响应集中返回可处理结果的回复与任务工作区记录。`max_chars` 是整批回复共享的 Unicode 字符预算，默认 20000，范围 1–100000。截断项需用 `waku_result` 进一步读取后再验收。

每项可处理结果带 `receipt`。管家完成该结果的验收、反馈或阻塞报告后，在交接中记录处理决定及凭据，并在下次查询的 `handled` 中显式提交。只有精确匹配时，响应才标记 `handled=true` 并省略回复与工作区记录。读取不会保存“已处理”、修改历史或撤销等待。调用方保留凭据，因此一次断连后的重读仍能返回未处理正文。

凭据绑定子会话、轮次和完整结果快照的 SHA-256，包含本轮消息与活动、失败原因、完整审批/问题和任务工作区证据。迟到输出或证据改变会使旧凭据失效；摘要不受返回文本截断影响。凭据用于调用方明确声明处理范围，不授予权限。跨项目和非直属目标仍整批拒绝。

独立评审指定完整提交和检查范围。同批发现集中发给对应负责人；普通反馈使用可靠输入及持久排队。证据仅在提交、检查范围和环境一致时复用，改动后检查受影响部分，保留独立评审和整体验收。没有独立工作时，只等待尚未解决的运行子会话，登记 `waku_wait` 后结束当前轮，由已有事件回调恢复。

## 受控任务证据

`cargo test -p waku-core mcp_coordination_batches -- --nocapture` 通过真实 MCP、daemon socket、临时 SQLite/Git 和可控 Codex/Claude 进程完成：实现者提交初版 → 指定提交的独立评审 → 一批反馈通过原生 steer 进入同轮 → 管家登记等待并结束 → 完成事件自动恢复一次 → 改后固定提交独立复核 → 验收整合 → 依赖子会话承接已接受提交 → 整体验收与本地交付。

本片首次通过时，fixture 从初始化到交付为 6032 ms。实际工具/原生 RPC 日志计数：无变化状态查询 0、重复未处理结果读取 0、反馈取消 0、原生 steer 1、完成回调 1。执行 4 次子任务检查，其中 1 次是相同提交、范围、环境的必要独立评审复核；可避免重复验证 0。最终组合检查另有 2 次。结果整合后新增证据使旧凭据失效，原提交证据仍绑定原版本。

这些数字只描述受控任务。测试驱动使用有界观测等待 fixture 屏障，未将这些测试观测算作管家工具查询。标题生成请求在可控 provider 中独立处理，不执行任务。没有调用真实模型或推断生产耗时/费用改善。持久 fallback、即时交流及清理/重开复用相邻票的公共回归，由 #22 在整合版本补全组合验收。

`mcp_results_batch_requires_explicit_handled_receipts` 覆盖读不自动处理、迟到输出、显示截断、用户问题换版、失败原因和直属权限。两种父 provider 的 `mcp_wait_*` 回归同时确认批量只读查询保留原等待，完成后只恢复一次。
