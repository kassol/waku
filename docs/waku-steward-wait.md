# 管家等待与完成通知

2026-09-06：用户确认采用“结束当前轮，回调后自动继续”。当前运行中的 Steward 和用户工作区不参与修改或测试；本轮产物不替换正在使用的 App。

## 行为

- 新增 `waku_wait(session_ids)`，仅接受当前管家同项目的直属子会话，并绑定登记时的子轮次。管家有独立工作时先完成自己的工作；需要等待时调用此工具，收到登记确认后结束当前轮，停止轮询。
- 已经结束或需要用户处理的子轮次直接返回当前状态，不登记等待。其他情况持久保存等待记录。重复登记相同目标返回同一记录。
- 管家真实完成当前轮后，界面显示“等待子会话”，可接收用户的新输入。子会话成功、失败、中断、权限审批或问题触发一次通知；流式文本不触发通知。
- daemon 在事件保存成功后唤醒独立工作线程。工作线程在事件锁外重新验证关系、轮次和父会话状态。父轮仍在工作时暂存等待；任何一个目标可处理后，自动开启一轮管家输入，明确标注自动子会话通知，引导管家读取结果并继续原任务。
- 通知消费与父会话新轮创建同时保存。重复事件不能重复提交。用户先发新消息、取消或父轮失败/中断时撤销旧等待。回调与用户操作必须在同一会话边界串行。
- 正常退出禁止自动唤醒。重启保留已确认的等待；恢复时子任务中断也属于可通知结果。父登记轮未正常结束的等待撤销。已保存但 provider 提交结果不确定的新轮保留历史并报告中断，不自动重发。

## 验证

使用临时数据库、临时工作区和可控 provider 验证登记、重复请求、父子结束顺序、通知去重、已有结果、直属权限、用户介入、重启和退出。覆盖真实 MCP 协议与 daemon 事件保存到回调提交的路径；状态显示复用原生会话与状态栏布局。

现有 `waku_status` 保留即时查询和兼容长轮询；工具说明引导需要暂停的管家使用 `waku_wait`，不以不断查询替代等待。此能力取代一期只有查询工具的限制，不引入定时调度或退出 App 后继续运行。
