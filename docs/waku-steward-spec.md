## Problem Statement

用户希望在 Waku 中只通过一个管家会话委派编码工作，由原生 Claude/Codex 会话独立执行，并随时查看各会话的状态与结果。当前需要手工创建和切换会话；会话之间缺少可持久保存的父子关系，事件转成可读历史并保存仍依赖桌面客户端。

本机已安装原版 Waku。开发和验收必须保护其安装、进程及自有数据。用户还需要明确知道哪些内容已经保存，以及任务因审批、错误、取消或退出而停止时发生了什么。

## Solution

一期提供 Claude 管家会话，通过六个 MCP 工具创建、驱动和查询直属 Claude/Codex 子会话。子会话默认使用独立 worktree；桌面侧边栏展示父子关系，用户可进入子会话阅读历史并处理审批或提问。

daemon 负责保存管家创建的会话、父子关系和会话历史，保证没有客户端正在查看该会话时仍能保存。用户可读历史保留到主动删除。界面区分已保存、待保存和保存失败；正式退出 App 时停止任务并等待保存，独立后台运行留到后续阶段。

## User Stories

1. 作为用户，我希望通过一个 Claude 管家会话描述工作，以便集中委派多个编码任务。
2. 作为用户，我希望继续使用原生 Claude/Codex，以便保留已有工具行为和服务配置。
3. 作为管家，我希望创建 Claude 子会话，以便委派适合该编码助手的工作。
4. 作为管家，我希望创建 Codex 子会话，以便在同一工作流中使用另一种编码助手。
5. 作为用户，我希望子会话默认使用独立 worktree，以便减少并行修改同一目录的冲突。
6. 作为用户，我希望可明确选择继承工作目录，以便让子会话接续当前目录中的工作。
7. 作为管家，我希望获知创建后的会话标识、目录及分支，以便继续跟踪工作。
8. 作为管家，我希望相同创建幂等键可返回同一创建结果，以便在响应丢失时避免重复创建和执行。
9. 作为管家，我希望创建失败能返回原因和已产生的会话信息，以便判断是否需要恢复或人工处理。
10. 作为管家，我希望列出自己创建的直属子会话，以便了解当前委派情况。
11. 作为用户，我希望每个管家只通过 MCP 管理直属子会话，以便保持各层委派职责明确。
12. 作为管家，我希望批量查询子会话状态，以便减少重复轮询。
13. 作为管家，我希望可等待状态变化或超时，以便在工作进行时获得有界响应。
14. 作为管家，我希望区分运行、等待用户、结束和失败，以便正确判断后续动作。
15. 作为管家，我希望读取子会话当前轮的回复和结束信息，以便汇总执行结果。
16. 作为管家，我希望可按需读取受长度限制的会话历史，以便补充理解而控制返回量。
17. 作为管家，我希望得知结果是否仍在生成、是否被截断，以便避免将片段当作完整结果。
18. 作为管家，我希望向可接收新一轮输入的直属子会话发送后续任务，以便延续工作。
19. 作为管家，我希望忙碌或等待审批时发送后续任务能得到明确反馈，以便避免不确定的重复执行。
20. 作为管家，我希望取消直属子会话当前执行，以便停止已无必要的工作。
21. 作为用户，我希望取消操作保留已经完成的历史和修改，以便检查或继续处理结果。
22. 作为用户，我希望在侧边栏看见会话父子关系，以便从管家定位到具体执行者。
23. 作为用户，我希望进入子会话后读到按原生顺序呈现的内容，以便准确理解执行过程。
24. 作为用户，我希望子会话权限不高于父会话，以便委派保持已有权限边界。
25. 作为用户，我希望亲自处理子会话的权限审批和问题，以便保留对相关决定的控制。
26. 作为管家，我希望看到子会话正在等待用户，以便避免误判为完成或无响应。
27. 作为用户，我希望没有打开某个子会话时，其内容仍能保存，以便稍后查看完整历史。
28. 作为用户，我希望长期会话的可读历史保留到我主动删除，以便不因内部日志清理丢失内容。
29. 作为用户，我希望能看见保存状态，以便知道突然退出后哪些内容可以恢复。
30. 作为用户，我希望磁盘满或持续保存失败时停止受影响任务，以便避免继续积累无法保存的结果。
31. 作为用户，我希望正常退出 App 时停止管家和子会话并保存，以便下次打开时继续检查工作。
32. 作为用户，我希望崩溃后恢复已确认保存的内容，以便明确数据恢复边界。
33. 作为用户，我希望客户端重连或旧快照写回不会擦掉父子关系和已保存历史，以便多次打开后的状态保持一致。
34. 作为用户，我希望删除某个会话不会隐式清理其他会话的历史，以便保留尚未决定删除的工作。
35. 作为原版 Waku 用户，我希望测试 App 使用独立的 Waku 资源，以便日常安装、进程和数据保持不动。
36. 作为用户，我希望测试仍可共用原生 Claude/Codex 配置和会话目录，以便沿用现有登录与服务配置。
37. 作为用户，我希望所有新增控件都可通过键盘操作，以便无需鼠标也能完成委派和查看。
38. 作为用户，我希望长历史和多个运行会话仍保持滚动与输入流畅，以便保留原生客户端的性能优势。

## Implementation Decisions

### 范围与结构

- 沿用管家会话、子会话、直属子会话、会话历史的已确认定义。首个可验收闭环为 Claude 管家创建 Codex 子会话、查询结束状态、读取结果；Claude 子会话也属于一期验收范围。
- 复用 daemon 二进制，新增 stdio MCP 子命令作为独立短生命周期进程，经现有 WebSocket 协议连接所属 daemon。保持单一 daemon 网络入口及其鉴权机制；stdio 的标准输出仅承载 MCP 协议，诊断写标准错误。
- MCP 实例绑定所属管家会话及项目，工具入参不得重新指定父会话以扩大范围。列表、查询、结果、后续输入和取消均强制限制到直属子会话；更深层委派由各层父会话管理。
- 这是 MCP 管理接口的访问边界，原生编码助手的文件和命令权限按其实际权限模式执行。避免把拥有通用桌面管理能力的接口直接作为模型工具暴露。
- daemon 提供统一的会话创建能力，负责验证项目与 provider、建立工作区、持久化会话和父子关系、启动运行时及提交首轮输入。MCP 调用复用此能力，未来调度能力也可使用相同入口；一期不实现调度器。
- Claude/Codex 启动适配支持按会话注入 MCP。使用原生启动参数或会话配置，不改写共用的 CLI 全局配置文件，不修改 harness 本体。子会话作为下一层管家时仍适用相同直属范围。

### 六个 MCP 工具

| 工具 | 输入与行为 | 返回及边界 |
| --- | --- | --- |
| `waku_spawn_session` | provider 和 prompt 必填；可指定 model、title、runtime_mode、workspace、idempotency_key。项目取自管家；workspace 默认 worktree，inherit 使用父会话的实际目录，local 使用项目的普通检出目录 | 返回 session_id、实际 workspace_path 和适用时的 branch。只允许 Claude/Codex，权限不得高于父会话。worktree 条件不满足时明确失败，禁止静默降级为共享目录 |
| `waku_prompt` | 对直属子会话提交一个新轮次的 prompt | daemon 持久保存输入及轮次标识后返回 turn_id，provider 后续失败通过状态报告。一期在已有开放轮次或等待用户时明确拒绝，调用方先查状态；不增加隐式排队或将新任务改为 steer 的行为 |
| `waku_status` | 查询 session_ids，可带 wait_ms；默认 0，允许 0 至 60000 毫秒，非法输入明确报错 | 返回每个目标的状态、最后活动、轮次是否开放及错误；等待审批或用户输入可被识别。长轮询在变化或超时后返回当时状态，不把超时当作任务失败 |
| `waku_result` | session_id，可选 include_transcript（默认 false）和 max_chars | 返回当前轮回复、真实结束信息和可选历史；当前轮未结束或尚无轮次时明确表示，不能退回上一轮成功结果。截断保留字符边界并给出截断标识，不修改存储中的历史 |
| `waku_cancel` | 请求取消直属子会话当前执行 | 可重复调用。区分取消请求被接受与 provider 已停止；不伪报成功完成，不删除历史或回滚 worktree，不隐式取消其他会话 |
| `waku_list_sessions` | 列出当前管家的直属子会话 | 返回摘要；原设计的 parent_only=false 扩大访问范围行为不提供 |

- `waku_prompt` 属于非幂等提交；连接中断造成接收状态不明时，不自动重发，并提示先查询会话状态。创建时使用幂等键解决重复创建：键按管家范围隔离；相同键和相同请求重试复用同一结果，不重复提交首轮；相同键不同请求明确冲突。映射必须在 daemon 重启后仍有效。未提供键时不承诺创建重试去重。
- 创建各阶段失败必须可观察；已经建立的会话和部分执行不得伪装成从未发生。只有本次新建且可证明未被使用的资源才能自动清理，已修改 worktree 和已有用户目录不得作为失败清理对象。
- 未找到、无权限、provider 不支持、权限提升、忙碌、运行时失败和保存失败均返回明确错误，不能用空结果或成功结果掩盖。错误不得泄露其他会话内容或凭据。
- 状态响应沿用现有会话状态 Idle、Connecting、Working、Waiting、Background、Failed，并同时给出当前或最近轮次的标识与 Running、Completed、Failed、Interrupted 状态；无轮次时明确为空。Waiting 额外说明等待权限审批或用户回答。开放轮次的成功结果尚未确定；取消受理不等于 Interrupted，只有停止确认后才收敛为中断。完成过上一轮的 Idle 不能被误判为从未运行。
- 回复提取以当前轮和原生事件顺序为准，保留连续文本被工具事件分隔时的正确结果。不能以简单读取最后几个文本增量代替轮次边界判断。provider 的正常结束只表示该轮正常结束，不等同于代码正确或用户目标已验收。
- 沿用现有输入和输出限制；所有模型提供的工具参数在入口验证。有限结果不能悄悄截断为貌似完整的结果。

### 权限、交互与生命周期

- 子会话继承父会话权限上限。跨 provider 采用不提升权限的映射；没有对应能力时明确拒绝该组合，不回退到更高权限。
- 权限审批和用户提问由用户在子会话现有交互中处理，管家获知等待状态。一期不增加管家代答工具，也不替用户自动回答问题。
- 在现有会话创建流程中提供管家入口，复用原生会话呈现和子会话详情。树形展示负责表达来源关系和导航；所有入口、层级操作和等待提示具备键盘路径及可见焦点。
- 单个管家轮次结束不等同于其子会话结束。取消工具只作用于指定会话；正式退出测试 App 时，由退出流程停止该实例管理的运行任务并完成保存。
- 删除会话沿用用户显式操作。删除父会话不隐式删除后代历史；剩余会话仍可被用户发现，并保留可解释的来源关系，不静默重新归属到其他管家。
- 一期正式退出 App 后不继续后台运行。正常退出先停止接收新任务，停止运行任务并处理尾部事件，等待可靠保存完成后结束所属 daemon。保存失败必须告知用户未保存内容，不能把失败当作成功退出保存；强制终止按异常退出保证处理。关闭窗口沿用现有平台行为。
- App 或 daemon 异常终止后，恢复已确认保存的数据，对于已确认失去运行时的未完成轮次标记为 Interrupted，运行状态不得永远停留在“正在运行”或“等待用户”；清除失效的审批与提问交互，后续新请求由新运行时产生。不会仅因重启自动重发不确定是否执行过的输入。继续执行由用户或后续管家操作明确发起。

### 持久化与兼容性

- daemon 自主保存会话、父子关系和按序事件，不能依赖某个客户端正在显示或处理该会话。新增事件持久记录与必要的父子关系、创建幂等记录；沿用现有数据库迁移和历史表示。
- 复用现有会话历史语义，必要时将可复用的历史归并逻辑从界面状态中分离，避免维护两份 provider 解释规则。具体组织方式在实现中选择最小有效改动，不锁定旧设计预估的行数或文件清单。
- “已保存”只能在数据获得可靠持久化确认后报告。接收事件、写入内存队列、发出保存请求均不构成保存确认。流式显示可先于保存，界面明确标示待保存与失败。
- 内部事件的 20000 条/90 天策略只可用于已安全保全可读历史、且满足恢复与重放要求的冗余事件。会话历史保留至主动删除；客户端长期未打开时也不能通过事件裁剪丢失历史。
- 队列压力不得通过丢弃转录处理，也不能在 UI 线程阻塞。持续写入失败时停止受影响任务并拒绝新任务，保留仍可恢复的数据，展示错误与未确认保存边界。
- 重放与在线流必须有明确衔接边界，按运行时与事件序列去重、保持顺序，避免重连、daemon 重启和重复事件造成重复消息或遗漏。事件清理不得破坏这个边界。
- 父子关系等 daemon 管理字段在创建、完整快照替换、落后快照合并、列表加载和详情加载中保持一致。客户端旧视图不得抹掉关系或覆盖更完整的已保存历史。
- 延续严格协议版本校验，协议变更同步更新所有受影响的 Rust 与 TypeScript 类型。不兼容版本在操作前明确拒绝；同版本多客户端和重复保存仍须正确处理，不能只靠升级版本保护字段。

### 测试 App 隔离与性能

- 首次测试启动前，验证并补齐应用及辅助程序身份、Waku 配置、数据库、daemon、工作目录、缓存和进程控制边界。测试 launcher 只连接并控制自己的实例，不因继承外部 daemon 环境变量而连接原版。
- 原版 App 的安装、运行进程和自有数据保持不动。普通原版身份的 Release 包不能用于测试；需要优化构建验证时，同样保留测试身份和数据边界。更新与清理操作不得跨越该边界。
- 允许共用现有原生 Claude/Codex 程序、配置与会话目录，并接受测试新会话共存。实际测试使用专用工作区和新会话，不主动续写、清理既有原生会话，不为测试修改共用服务配置。
- 渲染、测量与逐行构建只读内存；文件、数据库、网络和进程操作置于后台。历史与会话树按可见范围工作；重放、保存和多个流式会话不能把整段历史重建放进逐帧路径。沿用项目的流式节奏、虚拟化和性能验证方法。
- 新增控件支持键盘与系统减少动态效果设置；状态具备文字或图标，不能仅依赖颜色、悬停或动画。

## Testing Decisions

- 测试可观察行为：提交工具请求、观察返回及会话状态、断开或重启后读回历史、检查专用工作区和进程的结果。避免围绕私有函数拆出与实现逐行对应的测试。
- 主要自动回归入口为 MCP 工具协议，贯穿真实 daemon 业务处理、临时数据库及临时 Git 工作区。使用可控 provider 事件或测试进程替代外部模型，使顺序、故障和取消可确定复现。测试替身不得替掉被验证的持久化与访问范围逻辑。
- 复用现有 WebSocket 往返、认证拒绝、多客户端通知、迟到订阅者重放及重连测试模式；复用现有数据库迁移、消息往返、删除会话和延迟加载测试模式。仅在难以从公开入口稳定触发磁盘失败等情况时增加最小后台测试控制点。
- 创建闭环覆盖两种 provider、默认 worktree、显式共享目录、失败与幂等重试。验证 daemon 重启后同键不重复创建或提交首轮，冲突键明确失败；不依赖真实模型恰好重复或成功的概率。
- 工具回归覆盖直属范围、跨层和其他项目拒绝、批量查询与长轮询、忙碌输入、当前轮结果、工具穿插文本、截断、重复取消、等待审批和提问。结果中的结束状态不能代替代码验证结论。
- 数据回归覆盖没有查看会话的客户端、多个客户端、重复与重排事件、旧快照整对象替换、事件超过裁剪门槛、数据库重新打开、可靠保存确认前后异常终止，以及正常退出等待保存。验证可读历史无重复、无静默缺失，父子关系不被抹掉。
- 故障回归覆盖写入失败、启动失败、断连和退出竞态。验证停止受影响任务、拒绝新任务、错误提示和保存边界；不以一个 overflow 标记冒充完整恢复。
- 隔离回归使用临时的“原版”资源哨兵和独立测试资源，验证启动、保存、停止、辅助程序安装、更新与清理均不会修改或结束哨兵。对真实原版安装只做必要的只读核对，不能用破坏真实数据验证隔离。
- 实现验收时，在隔离通过且开发 watcher 成功重建、签名并启动的测试 App 中，走通 Claude 管家创建 Codex 子会话、查询完成和读取结果；另覆盖 Claude 子会话。检查父子导航、用户审批、保存状态和退出恢复。只使用新会话和专用工作区；本次规格发布不触发模型请求或运行测试 App。
- 原生 App 可见行为检查用于补足协议测试无法证明的键盘、树形呈现和状态提示；沿用项目长历史和流式性能验证。不得只凭 Rust 构建成功认定完整交付。
- 执行受影响范围的 Rust 格式、编译与测试，协议一致性检查，以及共享 TypeScript 客户端的类型检查和测试；按项目要求完成整体基线。每个非平凡逻辑变更保留最小有效回归，不额外搭建新测试框架。

## Out of Scope

- ACP 及其他 provider 的管家支持；修改原生 harness 本体。
- 定时任务与三个 schedule 工具，独立常驻服务及后台安装管理。
- harness 内部 subagent 细节、跨会话成本汇总与全局实时动作流；仅保留一期父子树。
- 管家通过 MCP 操作整棵后代树、用户手工创建的其他会话，或代答审批和用户问题。
- 保证尚未确认保存的数据在进程强杀或断电后仍可恢复。
- 测试环境强制隔离 Claude/Codex 原生登录及配置。
- 自动合并子会话代码、自动清理已修改工作区、自动续跑不确定提交，或重做现有所有客户端界面。
- 向上游仓库提交任何代码、Issue、PR 或评论；本规格发布与后续交付仅面向 fork。

## Further Notes

- 用户通过进入 `/to-tickets` 确认规格与测试边界；本规格标记 ready-for-agent，实施仍按后续拆分任务及授权边界进行。
- 本规格综合已确认的设计 v2 与 2026-09-06 澄清。历史设计中“队列满丢弃”“直接裁剪未保全事件”“默认筛选即可限制访问”“serde 默认值足以保留父子字段”和“退出 App 后一期继续运行”等表述不作为实现依据。
- 领域术语、历史保留、直属子会话权限、退出生命周期及测试隔离边界以仓库已确认的术语表和四份 ADR 为来源。后续发现需要改变这些行为时，先记录并确认决策变化。
- 这是可拆分的实施规格。后续使用 `/to-tickets` 创建带阻塞关系、各自可验收的纵向任务；隔离与构建基线应先于真实 App 和 provider 验收。每票实现后完成 Standards 与 Spec 两轴评审。
- 发布规格不解除暂缓安装 Rust 工具链和功能实现的约束，也不表示上述能力已经实现或验证通过。
